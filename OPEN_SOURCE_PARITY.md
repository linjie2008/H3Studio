# MiniMax H3 Director feature parity audit

Updated 2026-10-09 against the repositories' current default branches. This compares creator-facing behavior, not node names. The primary references are AIMixer's multi-segment Director, ajufeng's current v2.40.2 Director, and imbutus's structured timeline compiler. The first two focus on end-to-end ComfyUI generation and memory control; imbutus focuses on timeline editing, role-aware attachments, prompt compilation, and linting. Their feature sets differ, so a feature is not assumed to exist in all three.

Reference implementations:

- [AIMixer / ComfyUI_MiniMaxH3_Director](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director) — current mainline Director node pack.
- [ajufeng / ComfyUI-MiniMaxH3-Director](https://github.com/ajufeng/ComfyUI-MiniMaxH3-Director) — v2.40-era adaptation with project library and AI story tools.
- [imbutus / ComfyUI-MiniMaxDirector](https://github.com/imbutus/ComfyUI-MiniMaxDirector) — structured H3 prompt compiler, entity cards, dialogue and linter.
- [Comfy-Org H3 prompt guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide) — current three-field layout, dialogue/speaker, voiceover, audio lanes, and visible-text rules used by the compiler.

These items are separated from ComfyUI-only installation helpers: H3 Studio is a standalone creator app and only uses ComfyUI's base generation API plus its own extension nodes.

### Memory optimization added in this build

**项目设置 → H3 显存策略 → 按显存自动调整** reads ComfyUI `/system_stats` and queue state for each selected shot and stores requested/effective H3 dimensions, VRAM values, budget, and reason in the run report. It is opt-in and defaults to **按项目画布**. Current bands are heuristic (0.40 / 0.60 / 0.78 / 1.04 MP); low free VRAM lowers an idle queue to 0.40 MP, while a busy or unknown queue makes the planner ignore transient free memory. It also constrains latent-refine canvas. On this RTX 5090 Laptop (23.9 GiB reported), a 1920×1088 request planned to 1152×640 at 0.78 MP while the queue was idle. No render was submitted for this check. This is not a no-OOM guarantee and does not copy upstream DynamicVRAM or custom attention algorithms.

## Memory behavior in this build

The memory optimizations are partial. The runner checks ComfyUI's free CUDA memory after each completed shot and asks ComfyUI to unload cached models if free VRAM falls below 15% of total or 2 GiB, but only when the ComfyUI queue is idle; if another prompt is running or queued, it records the skip and preserves that task. Enable **高级生成参数 → 镜头间显存清理** to request cleanup after every shot when the queue is idle. Cleanup can reduce memory retained between shots and can increase time because later shots may reload weights. SeedVR2 is submitted as a separate ComfyUI task so H3 models can be unloaded before upscale; its VAE is tiled and both VAE and DiT use CPU offload with model caching disabled. SelfLift's high-resolution stage can use spatial tiling.

The project setting **项目设置 → H3 显存策略 → 按显存自动调整** is opt-in. It reads `/system_stats` and the ComfyUI queue before each selected shot, then records requested/effective dimensions and its reason in the run report. If stats are unavailable it falls back to a 0.40 MP budget. If queue state is unknown or busy, transient free memory is ignored. For latent refinement it applies the same pixel budget and keeps the target at least as large as the planned base canvas. The current GPU-capacity bands (0.40/0.60/0.78/1.04 MP) are local conservative heuristics; they are not upstream Director behavior and do not promise an OOM-free render. The official H3 guide recommends staying around its 1 MP native canvas and upscaling separately; this policy permits 1344×768 (1.032 MP) native landscape dimensions but caps larger canvases at 1.04 MP. The project canvas remains the final merge/export size. See [ComfyUI's H3 guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3).

H3 Studio does not automatically select SeedVR2 tile size or sampling mode. It also does not claim to reproduce Director's native latent carry or its full internal cache format.

## Next implementation order

1. Add explicit audio reference relationship markers, cross-cut dialogue continuation, and deeper guide-based lint checks to the compiler.
2. AI story, character extraction, storyboard drafting, and full-script polish using the configured local or remote provider, with explicit review before replacing shots.
3. Expand subject profiles into reusable people/prop/place/style cards with multiple visual, motion, and voice assets and reference-strength controls.
4. Complete visual editing parity: source thumbnails and draggable cut points, storyboard groups, drag/drop, waveform and frame ruler.
5. Add report/linter, retake stitching, and independent video upscale where available tools support them.
6. Expand Director pack round-trip and per-shot timing/cache compatibility tests; keep VRAM-gated features disabled unless compatible models are installed.
